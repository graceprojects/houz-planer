# HOUZ PLANER — планировщик пространства

Личный веб-инструмент для подготовки планировочного задания дизайнеру. Начальный проект — офис 40 × 12 м с высотой зала 6,6 м и вторым ярусом 120 м² (25%).

## Как пользоваться

1. Перетащите карточку мебели на план. Можно нажать карточку, затем место на плане.
2. Потяните предмет за середину, чтобы передвинуть. Угловые ручки меняют размеры, круглая — поворот. Точные значения в миллиметрах — справа.
3. Стена / Витраж / Дверь / Окно открывают слева свой каталог. Выберите вариант и размеры, затем нарисуйте стену или нажмите на стену для проёма. Двери и окна можно также перетаскивать из каталога. «Пространства» открывает готовые кабинеты и открытые зоны; внутри каталога остаётся кнопка ручного рисования комнаты.
4. Потяните перегородку поперёк: примыкания сохраняются, площади пересчитываются. Концевые точки меняют длину.
5. Нажмите на пол помещения для названия, цвета и пожеланий. Экспликация внизу раскрывается в таблицу.
6. Пробел + перетаскивание временно включает руку в 2D и 3D. Magic Mouse / трекпад: жест по поверхности перемещает вид, Option (⌥) + жест меняет масштаб, щипок трекпада тоже приближает. Для обычной мыши выберите режим внизу: колесо меняет масштаб. Клавиши + / − — масштаб, 0 или F — вписать этаж. Пробел в текстовых полях работает как обычно. В 3D обычное перетаскивание вращает модель; «Срез стен» показывает интерьер, «Оба этажа» — весь объём.
7. Кнопка «Дизайнеру» открывает печатное задание, SVG, CSV и редактируемый файл. В печати выберите PDF, A3, масштаб 100%.
8. Меню названия проекта: новые проекты, копии, сохранённые варианты и открытие файла .office.json.

Проект сохраняется автоматически в личную базу после входа. Временный черновик в браузере помогает восстановить несохранённые изменения. Файл .office.json — переносимая резервная копия. Конфликт разных окон не перезаписывает чужие изменения: редактор предлагает сохранить копию.

35 типов мебели с изометрическими карточками, 7 комплектов, 7 вариантов стен и витражей, 6 вариантов дверей/проёмов, 4 варианта окон, библиотека готовых назначений помещений. Размеры предметов — стартовые типовые значения, которые можно менять.

## Границы первой версии

Прямоугольные стены и помещения, один первый этаж и один прямоугольный второй ярус в торце. План можно менять в реальном масштабе, но это концептуальное задание, а не BIM-модель и не проверка строительных норм. Площади считаются по внутренним граням стен без дверных порогов; проёмы лестниц исключаются на верхнем ярусе. 3D использует собственные лёгкие параметрические модели. Это условная мебель для планировки, не изделия конкретных производителей. Высота столов и стоек задаёт высоту самой мебели; монитор, смеситель и предметы на поверхности могут быть выше. Фурнитура может выступать на несколько сантиметров за основной габарит. Импорт Revit RFA и библиотек производителей не реализован. Геометрические предупреждения проверяют границу этажа и пересечение мебели с перегородками.

## Локальный запуск

Открывайте http://localhost:5173/. Ярлык запуска в папке проекта: `output/sales_office_planner/ЗАПУСТИТЬ_ЛОКАЛЬНО.command`. Данные локальной версии хранятся в `.wrangler/state` и не отправляются на опубликованный сайт. Последний открытый проект запоминается отдельно для каждой вкладки.

## Разработка

Node >= 22.13, npm install, npm run dev. Сборка: npm run build. Стек: React, Vinext, Three.js, Cloudflare D1. Конфигурация сайта — .openai/hosting.json. Секретов в исходниках нет.

Миграция D1: drizzle/0000_heavy_mongoose.sql. В production миграции поставляются в архиве сборки через Sites. Локальная база изолирована от production. Владение проектами проверяется на сервере.

Проверка типов: node node_modules/typescript/bin/tsc --noEmit.
Проверки геометрии: ./node_modules/.bin/esbuild tests/geometry.test.ts --bundle --platform=node --format=esm --outfile=.sites-runtime/geometry-test.mjs, затем node .sites-runtime/geometry-test.mjs.

Файлы Blender не изменяются этим приложением.

Проверки навигации и проёмов: соберите `tests/navigation.test.ts` через esbuild аналогично тесту геометрии, затем `node --test .sites-runtime/navigation-test.mjs`.

## Детальная мебель

- Выберите предмет: справа показываются его объёмная карточка, готовые отделки и точные размеры. У мягкой мебели предлагаются цвета обивки; у столов и шкафов — дуб, орех, белый и графит. «Свой цвет» сохраняет выбранный вручную оттенок.
- «Предметы на поверхности» убирает или возвращает монитор, клавиатуру, книги, чашки и другие дополнения без удаления мебели.
- «Рассмотреть в 3D» приближает и показывает выбранный предмет отдельно. «В интерьере» возвращает его окружение; круговая стрелка возвращает весь этаж.
- Детализация «Авто» показывает больше деталей при приближении. Вручную доступны «Детально» и «Упрощённо». Неподвижный 3D-вид не перерисовывается постоянно.
- Отделка и комплектация сохраняются в проекте и включаются в печатную ведомость дизайнеру. Разные отделки одного предмета учитываются отдельно.

Исследование и принятые решения: [docs/FURNITURE_REVIEW.md](docs/FURNITURE_REVIEW.md).
Проверки мебели: соберите `tests/furniture.test.ts` через esbuild аналогично геометрическим тестам, затем запустите полученный файл через `node --test`.

## Состав офиса и готовые пространства

**Пространства → Состав офиса**: основы 200 / 400 / 600 м² из пользовательского задания. 28 функций, четыре группы, количество и площадь каждой функции, резерв общих проходов и стен, баланс по формуле net / (1 − reserve). Вкладка «Как связать зоны» объясняет клиентский маршрут и соседства. «На плане» сравнивает заданный состав с размещёнными пространствами и назначенными комнатами.

Перетаскивайте готовое пространство из каталога на свободное место. Кабинеты включают стены 150 мм, дверь 900 мм и представительную мебель; публичные зоны и шкафы остаются открытыми. Фон или подпись переносят весь блок, угловые точки меняют его размеры. Размеры самой мебели сохраняются. Точные размеры и цвет доступны справа; мебель можно править отдельно. «Разобрать на элементы» освобождает стены и мебель для независимого редактирования.

Существующей комнате можно назначить «Функция в составе офиса». Это не добавляет новые стены. В экспликации вкладка «Пространства» показывает функции отдельно от физических помещений: открытые зоны не прибавляются к площади зала повторно. Состав, пространства и назначенные функции сохраняются в JSON и локальной базе, входят в печатное задание; зоны видны в 2D / 3D.

«Пустой вариант в этом контуре» создаёт отдельный проект с текущими габаритами и ярусом. Выбор основы состава не меняет габарит здания и не расставляет полный офис автоматически. Вход, лестница и взаимное положение зон выбираются пользователем. Защита размещения проверяет существующие стены, предметы, другие пространства и границу этажа; подсказки соседства не являются автоматической проверкой маршрутов, акустики или строительных норм. Санитарные и технические заготовки резервируют площадь, а не заменяют детальный инженерный проект.

Правила для дальнейшей работы агента: [проектный skill](docs/skills/sales-office-planning/SKILL.md). Он хранится вместе с исходниками; глобальная установка не выполнялась. Исходный пользовательский текст включён в репозиторий: [состав офиса продаж](docs/references/sales-office-programme.ru.md). Оригинал также сохранён в папке BROADWAY.

## Репозиторий

Репозиторий содержит приложение, собственную библиотеку мебели, правила планирования офиса, тесты и документацию. Локальная база сохранённых пользовательских планов (`.wrangler/state`), временные файлы и параметры входа не входят в Git. Для переноса конкретной планировки используйте «Дизайнеру → Редактируемый проект» в приложении.

## GitHub Pages

Публичная версия: https://graceprojects.github.io/houz-planer/

`npm run build:pages` собирает самостоятельный сайт в `dist-pages/`;
`npm run preview:pages` запускает проверку сборки. Исходники остаются в `main`,
готовые файлы публикуются в `gh-pages` (Pages → Deploy from a branch → gh-pages /).
При обновлении сайта нужно повторно собрать и загрузить содержимое `dist-pages/`
в эту ветку, сохранив `.nojekyll`.

Эта версия использует IndexedDB браузера с проверкой версии при сохранении.
Облачный API и вход не нужны. Планы не синхронизируются между устройствами;
очистка данных сайта удаляет локальные проекты. Для переноса с localhost или
резервной копии используйте «Скачать файл проекта» / «Открыть файл проекта».
Существующая серверная версия и её база данных остаются отдельными.
